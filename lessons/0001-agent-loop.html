PI FIELD NOTES / LESSON 01

智能体的第一圈

不是“给模型一段厉害的提示词”，而是让程序根据模型的请求执行工具，再把真实结果交回模型。

约 10 分钟 · 先会 Python 就够了 · 教材：D:\pi，提交 9841914（2026-09-05）

01 / 今天只学一件事

谁决定，谁执行，谁记住？

在 Pi 这种工具调用型智能体里，模型决定下一步想做什么；你的程序决定能不能做，并执行它；消息列表保存已经发生的事。“智能体”指这整套工作系统，不是某个特殊的模型对象。

模型提出动作 → 程序执行工具 → 结果进入上下文 → 模型再决定。

你不用先训练模型，也不用先学 LangGraph、向量数据库或多智能体框架。先理解这个反馈闭环。这里的模型通常通过 API 调用；Pi 的 pi-ai 把不同供应商接口适配成统一协议。

原始依据：agent README：With Tool Calls；agent-loop.ts：runLoop，156–273 行。

02 / 一次完整轨迹

把 23 + 19 交给工具

这是故意简单的例子：不需要工具也能算，但很适合看清控制权。真实任务可把 add 换成 read、数据库查询或测试执行。

  1. user
    “用 add 工具计算 23 + 19。”
  2. assistant
    模型返回结构化请求：{id: "call-1", name: "add", arguments: {a: 23, b: 19}}。此时加法函数还没有运行。
  3. toolResult
    程序找到函数、校验参数、执行 add(23, 19)，把 42 及 toolCallId="call-1" 加入消息。
  4. assistant
    第二次调用模型，输入里已经有真实工具结果。模型给出最终答案，若没有新工具请求，也没有排队输入，就结束。

toolCallId 像请求编号：多个工具同时返回时，它告诉模型“这个结果对应哪次调用”。不要只保存工具结果而丢掉 assistant 的调用请求。

数据结构：ai/types.ts：ToolCall（373 行）、ToolResultMessage（452 行）。

03 / 用 Python 看骨架

你已经会写其中大多数代码

以下是协议示意，不是可直接联网运行的 SDK 代码。model() 与 execute_tool() 是我们定义的边界，不是 Python 内置函数。

def run_agent(user_text, model, tools, max_turns=5):
    messages = [{"role": "user", "content": user_text}]

    for _ in range(max_turns):
        # 只给模型工具的名称、说明和参数 schema
        reply = model(messages, tool_descriptions(tools))
        messages.append(reply)

        check_model_status(reply)  # 错误、取消、截断不能冒充成功
        calls = [b for b in reply["content"]
                 if b["type"] == "toolCall"]
        if not calls:
            return messages

        for call in calls:
            result = execute_tool(call, tools)
            messages.append(result)  # 下一轮模型能看到结果

    raise RuntimeError("超过轮数预算")

关键不是 for 还是 while，而是“下一次决策依赖上一步的观察结果”。模型的最终回答不自动证明任务成功；例如它说测试通过，还应核对测试工具的输出。

发送给模型的部分

name、description、parameters。相当于函数的使用说明书。没有本地 Python 函数对象。

留在程序里的部分

execute。相当于注册表中的真实函数；模型只能请求，由宿主程序执行。

Pi 的对应实现：212 行请求模型；222 行提取工具；237 行回填结果；625 行校验参数；686 行执行工具。轮数预算是本课的保护措施，不是声称 Pi 在该函数中硬编码了 5 轮。Pi 另有停止钩子与取消能力。
