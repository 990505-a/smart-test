**Body sections (in Chinese):**

1. `## 激活场景` -- When the agent should query wiki:
   - 需求文档引用了业务规则或技术规范时
   - 用户提到具体项目名称或系统模块时
   - 需要了解已有测试标准和最佳实践时
   - 需求分析阶段发现领域专业术语需要解释时
   - 测试策略制定需要参考历史测试经验时

2. `## 工具使用指南` -- Guide for each of the 6 wiki-mcp tools (per D-05, these are auto-exposed via MCP protocol):
   - `list_wikis`: 首先调用，了解可用的知识库项目
   - `search`: 主要查询工具，支持中英文关键词，使用 query 参数搜索。可用 type 过滤页面类型，maxTokens 控制返回大小。搜索结果包含 wiki 的 purpose.md 上下文
   - `get_page`: 读取特定页面全文，使用 path 参数（从 list_pages 或 search 结果获取）。related=true 可获取关联页面
   - `list_pages`: 按类型或标签浏览页面。type 可选: entity/concept/source/query/synthesis/comparison
   - `graph_query`: 知识图谱查询。三种模式: neighbors（发现关联页面）、stats（图谱统计）、trace_source（追溯引用来源）
   - `reload`: 当知识库文件有变更时调用重建索引

3. `## 与工作流的集成` -- How wiki results feed into the 5-stage workflow (per D-07, does NOT change workflow structure):
   - 需求分析阶段(requirement-analysis): 主动搜索 wiki 获取项目领域知识、业务规则定义。将检索到的知识标注 [Wiki:来源] 纳入功能矩阵
   - 测试策略阶段(test-strategy): 查询 wiki 获取测试标准和历史经验。参考已有测试策略作为制定依据
   - 用例设计阶段(test-case-design): 如需补充领域知识，查询相关页面获取细节
   - 其他阶段通常不需要查询 wiki

4. `## 查询策略建议`:
   - 优先使用 search 工具进行关键词检索
   - 使用 graph_query(neighbors) 发现知识关联
   - 使用 get_page(related=true) 获取页面及其关联内容
   - 查询结果应标注来源 [Wiki:页面路径]
   - 如果 wiki 知识与用户需求冲突，以用户当前需求为准（在分析报告中标注冲突）

5. `## 输出规范`:
   - 查询结果应整合到对应阶段的分析输出中
   - 引用 wiki 内容时标注来源
   - 未检索到相关知识时，在分析中注明"未从知识库获取到相关参考"
