6. **Dual-source merge logic** (critical):
   ```
   mergedMessages = useMemo:
     if streaming is active (stream.isLoading):
       // Stream messages are the source of truth during active streaming
       // Merge: take paginated history as base, overlay streaming messages
       // Deduplicate by message.id (stream version wins)
       const merged = new Map();
       // Add paginated messages first
       for (const msg of paginatedMessages) { merged.set(msg.id, msg); }
       // Override with streaming messages (more current)
       for (const msg of stream.messages) { merged.set(msg.id, msg); }
       return Array.from(merged.values());
     else:
       // Not streaming: use paginated messages only
       return paginatedMessages;
   ```

7. Return `mergedMessages` instead of `stream.messages` from the hook. Keep `stream.messages` accessible for the merge but don't expose it directly as the primary messages array.

8. Add `isLoadingHistory` and `loadOlderMessages` to the return value, delegating to usePaginatedMessages.

9. IMPORTANT: The `processedMessages` logic in ChatInterface.tsx currently walks `messages` sequentially to match AI messages with tool calls. This logic MUST still work with the merged messages. The paginated messages from the backend already include tool messages in conversation groups (Plan 01 ensures this), so sequential walking within a page works. The merge deduplicates by ID, so tool messages won't appear twice.

Modify ChatInterface.tsx to use Virtuoso for message rendering:

1. Remove `useStickToBottom` import and usage. Replace with Virtuoso:
   ```typescript
   import { Virtuoso, type VirtuosoHandle } from "react-virtuoso";
   ```

2. Remove `useStickToBottom()` call and its `scrollRef`/`contentRef`.

3. Remove the manual auto-scroll `useEffect` (the one with `requestAnimationFrame` and `scrollTo`).

4. Add Virtuoso refs and state:
   ```typescript
   const virtuosoRef = useRef<VirtuosoHandle>(null);
   const [isAtBottom, setIsAtBottom] = useState(true);
   ```

5. Destructure new fields from `useChatContext()`:
   - `isLoadingHistory` (boolean)
   - `loadOlderMessages` (() => void)
   These come from the modified useChat hook (Task 1).

6. Replace the message list rendering section. Currently it's:
   ```html
   <div ref={scrollRef} className="flex-1 overflow-y-auto ...">
     <div ref={contentRef} className="mx-auto ...">
       {processedMessages.map(...)}
     </div>
   </div>
   ```

   Replace with:
   ```html
   <Virtuoso
     ref={virtuosoRef}
     data={processedMessages}
     followOutput={isAtBottom ? "smooth" : false}
     atBottomStateChange={setIsAtBottom}
     atTopStateChange={(atTop) => {
       if (atTop && hasOlderMessages && !isLoadingHistory) {
         loadOlderMessages();
       }
     }}
     increaseViewportBy={{ top: 200, bottom: 200 }}
     defaultItemHeight={80}
     components={{
       Header: () => isLoadingHistory ? (
         <div className="flex justify-center py-4">
           <span className="text-sm text-muted-foreground">加载中...</span>
         </div>
       ) : null,
     }}
     itemContent={(index, data) => {
       const isLastMessage = index === processedMessages.length - 1;
       const messageUi = uiMap.get(data.message.id ?? "");
       return (
         <div className="mx-auto w-full max-w-[1024px] px-6">
           <ChatMessage
             message={data.message}
             toolCalls={data.toolCalls}
             isStreaming={isLastMessage && isLoading}
             ui={messageUi}
             stream={isLastMessage ? stream : undefined}
             graphId={isLastMessage ? assistantId : undefined}
           />
         </div>
       );
     }}
   />
   ```

7. `hasOlderMessages` comes from the useChatContext return (from usePaginatedMessages).

8. The `processedMessages` useMemo stays mostly the same -- it processes the `messages` array from useChatContext into the `{message, toolCalls}[]` format. It already handles AI+tool matching sequentially. The key difference is that `messages` now comes from the merged paginated+streaming source instead of directly from useStream.

9. Remove the empty state handling from the Virtuoso component. Instead, handle it above Virtuoso:
   - If `processedMessages.length === 0`, show the "智能测试平台 / 输入消息开始对话" empty state
   - Otherwise, render Virtuoso

10. Ensure Virtuoso fills the available space: wrap it in a div with `className="flex-1"` and Virtuoso should get `style={{ height: '100%' }}` or use the `customScrollParent` prop if needed. Virtuoso needs a container with defined height to work.

11. DO NOT change ChatMessage.tsx. It is already React.memo'd and works with individual message objects. Virtuoso passes one item at a time, which is compatible.

12. DO NOT change ChatProvider.tsx. The provider just wraps useChat, which now returns paginated data transparently.
