评测集字段、分数名与门禁语法

写用例、读分数、写门禁时对着抄。所有条目都对应本仓库当前实现（src/app/eval/）。

第 1 课 本速查卡 MISSION

1 · 评测集文件（datasets/*.yaml）

字段必填说明
name✓评测集名（批次名会用它拼 name@release）
description一句话说明这个集子测什么
agent✓被测智能体（LangGraph 图名：testcase_agent / webui_agent / unity_agent / codebase_agent）
max_repair数据集级声明（当前网页路径未接入，见 EVAL.md「已知限制」）
items[]✓用例列表，见下

item 的三个字段

字段子字段含义 / 产出的分数
id—用例标识（页面与 Langfuse 里都用它认人）
input—交给智能体的任务原话（也是 trace 的 input）
expectedcontains: [...]最终答复须包含其中任一片段 → task_output_match
not_contains: [...]不得出现的片段 → no_forbidden_content
tools: {sequence: [...], mode: subsequence|exact}工具调用序列 → tool_sequence
max_tool_errors: N工具报错预算 → tool_errors（数值，越小越好）
evidence: [...]须产出的产物路径（支持单个 *）→ evidence_exists
judgecriteriaLLM 裁判的评审标准（写"判不通过的条件"更有约束力）
pass及格线（0–1，常用 0.6–0.7）→ 产出 llm_judge 与 llm_judge_pass

分数是按需产出的：字段没写，对应分数就不存在（不是 0 分）。门禁里写了不存在的分数会直接判失败。

2 · 分数名对照表

分数名类型产出者门禁里怎么用
task_output_matchBOOLEAN确定性：答复包含期望片段all(task_output_match)
no_forbidden_contentBOOLEAN确定性：未出现禁止内容all(no_forbidden_content)
tool_sequenceBOOLEAN确定性：工具调用序列符合期望all(tool_sequence)
tool_errorsNUMERIC确定性：工具报错次数max(tool_errors)<=2
evidence_existsBOOLEAN确定性：期望产物真的存在avg(evidence_exists)>=1
webui_case_pass_rateNUMERICWeb-UI：从 Playwright CLI 报告读到的用例通过率avg(webui_case_pass_rate)>=0.8
webui_cases_all_passedBOOLEANWeb-UI：这次执行是否零失败all(webui_cases_all_passed)
llm_judgeNUMERICLLM 裁判原始分（0–1）avg(llm_judge)>=0.6 / min(llm_judge)>=0.4
llm_judge_passBOOLEANLLM 裁判是否过阈值all(llm_judge_pass)

布尔分数在门禁里按 1/0 参与 avg/min/max；CATEGORICAL 类型会被跳过。

3 · 门禁语法

avg(分数名) >= 0.8      该分数在所有用例上的平均
min(分数名) >= 0.6      最差的那条用例
max(分数名) <= 2       最坏情况的护栏（配 tool_errors 这类"越小越好"的分）
all(布尔分数名)         每条用例都必须为真

用 && 串联多个子句（也接受逗号）：
avg(task_output_match) >= 0.8 && all(tool_sequence) && max(tool_errors) <= 2
  • 比较符支持 >= <= > < ==；all(...) 不带比较符。
  • fail-closed：写了没人产出的分数名 → 判失败（防止打错字变成"没有约束"）。
  • 留空门禁 = 不设约束：批次状态只看有没有执行异常。
  • 页面里选完数据集会自动带一条推荐门禁（由该集子实际会产出的分数推导）。

4 · 批次状态判定

状态条件
passed门禁通过 且 执行异常数 = 0
failed门禁未通过，或有执行异常但未全挂
error所有用例都执行异常（环境级故障）
running + 疑似中断记录仍是运行中，但执行进程心跳已停（容器重启 / 被 kill）

passed ≠ 分数高。异常只看"用例有没有跑起来"。要抓分数，必须写门禁。

6 · 五个常见坑

  1. 评测集写在哪：页面保存的是仓库 datasets/ 下的真实文件（已挂载进容器，改完立刻生效、不用重建镜像）。手改这些文件也可以——但别改 datasets/specs/ 之类别的目录，那不在读取范围内。
  2. 两个 SQLite 库：容器（网页 / docker compose exec）用 docker-data/smart_test_platform.db；宿主机直接跑 CLI 用仓库根目录的库 → 命令行跑的批次在网页上看不到。
  3. 把确定性期望写进 judge：能机器判的（包含某词、调用过某工具）写进 expected，judge 留给语义判断。judge 慢、贵、还会抖。
  4. 门禁留空：全跑通就 passed，分数再低也是绿灯。
  5. judge 默认继承主 LLM：设置页「LLM 裁判（测评打分）」三项留空 = 用主模型（测评页卡片会写明「继承主 LLM」）。真做回归时要配一个独立模型——同一套偏好同时影响被测行为和评判，分数就不独立了。配完点「测试连通」：它走的是真实打分通道（JSON 模式），能过就等于能判分。
  6. 把"没有分数"读成"0 分"：字段没写就没有那个分数；门禁里写不存在的分数会 fail-closed。
