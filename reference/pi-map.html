组装和运行是两件事：createAgentSession 像 Python 的 factory，挑模型、资源、存储并连接组件；runLoop 才是每次任务反复运行的主体。

哪些必须有，哪些先别加？

把“最新必须部分”拆成两个问题：最小闭环需要什么，以及这份新近源码多了什么。不要把“新”误认为“必需”。以下是针对 Pi 这种工具调用型 LLM 智能体的教学划分，不是所有智能体的唯一分类。

层次能力为什么
最小闭环模型入口、输入/上下文、决策循环和停止条件接收任务，产生决定，记住结果，并能结束。
工具型 agent 必需工具说明/schema、调用分发、执行结果回传让模型请求真实动作，并根据观察继续。
面向真实使用参数校验、权限/隔离、取消/超时、预算、错误语义、日志与评估防止错误动作、无限循环和“声称成功却没做成”。
长任务按需持久化、上下文压缩、崩溃恢复、幂等策略对话可能很长，进程可能中断，外部副作用可能不确定。
可选增强流式 UI、RAG、长期记忆、多 agent、MCP、专门的 planner、skills解决特定需求，不是先搭最小闭环的前置条件。

明确任务与约束很重要，但 systemPrompt 不必是独立、非空的字段：Pi 的 ai Context.systemPrompt 是可选的，Agent 默认也可用空字符串。工具数量也没有硬性“四个”标准；Pi 编码代理默认是 read / bash / edit / write。

安全不是一句提示词。Pi 根 README 明确：它不自带限制文件、进程、网络、凭据访问的权限系统，默认继承启动进程权限。工具前钩子可以拒绝调用，但不等于操作系统沙箱。让 agent 接触真实文件/命令时，应另设隔离和授权边界。

依据：README：39–47 行；sdk.ts：256 行；coding-agent README：495–509 行。

本地 0.85.0 快照，别混淆两条路线

路线 A · Agent + AgentSession

Agent 是入门最清楚的带状态循环：消息、流式事件、工具执行、steering/follow-up 队列、取消。常规 coding-agent 的 SDK 在它外面组装 AgentSession；会话管理器使用 JSONL 树记录历史与分支。Agent 自身的内存消息不等于持久化数据库。

路线 B · AgentHarness 持久化运行时

AgentHarness 规范与 runtime 源码目录包含 Session、Lane、Operation、恢复和持久化状态机。它关心的不只是“下一步做什么”，还有“进程死在工具执行中间，重启后怎么继续”。不要将其直接等同于路线 A 的 runLoop。

准备输入 → 提交执行意图 → 执行外部动作 → 提交结果/下一状态

比如发出动作后进程崩溃，动作可能已经成功、但结果还未保存。恢复时不能无脑重试所有写操作；规范区分 replay: "never" 与 "safe"。它不保证外部副作用 exactly-once。

规范 §0.9 明确列出未实现或未完成部分，包括 watchSession 桩、遥测传播和部分 fork 工作。因此这份课程不把整份设计文档当作“全部已经实现”。

这份源码中已经可见的核心细节

  • 低层 Agent 默认并行执行允许的工具；如批次有顺序工具，则整个批次顺序执行。完成事件可乱序，最终结果消息按模型原顺序排列。
  • beforeToolCall 在参数校验后运行，可阻止工具；afterToolCall 可调整结果。
  • 模型输出被 token 上限截断时，该回复中的工具调用不会直接执行，而是产生错误结果。
  • 调用模型前可先 transformContext，再 convertToLlm，分离应用消息与供应商能理解的消息。

TS → Python：先认这 9 个形状

它们是心智类比，不是逐字语法转换。尤其注意：TypeScript 类型通常在运行时被擦除；interface 不会自动校验模型输出。Python 的 TypedDict / 类型注解同样不会自动校验。

TypeScriptPython 类比 / 注意点
interface Tool { name: string }TypedDict 或 Protocol：描述结构，不创建对象。
class Agent、this.stateclass Agent、self.state。
async f(): Promise<T>async def f() -> T；await 后得到 T。JS Promise 与 Python coroutine 的启动语义不同，不是完全等价。
for await (const e of stream)async for e in stream：消费异步事件流。
items.filter(x => x.type === "toolCall")[x for x in items if x["type"] == "toolCall"]。
const next = {...state, messages: [...]}next = {**state, "messages": [...]}；两者都是浅层复制。
value ?? fallback仅 null/undefined 时用后备值。近似 fallback if value is None else value，不是 Python 的 value or fallback。
config.hook?.()存在 hook 才调用。近似 hook() if hook is not None else None。
type Message = User | Assistant | ToolResult联合类型，用 role 区分分支；类似带 Literal 标签的 TypedDict 联合。

TypeBox 与 Pydantic 的桥梁

Type.Object({path: Type.String()}) 是运行时 schema 数据；Static<typeof schema> 推导编译期 TS 类型。可以把其用途类比为“Pydantic 模型同时提供字段描述和校验”，但 TypeBox schema 本身不是 Python 类；Pi 在工具执行边界显式调用 validateToolArguments。

术语小字典

Model / 模型
产生文本或工具请求的决策来源；不是整个 agent。
Provider / 供应商适配器
处理认证和协议差异，把通用调用转换到具体服务。
Tool / 工具
模型可请求的能力；包含说明、参数 schema 和宿主中的实现。
Context / 模型上下文
本轮实际发给模型的指令、消息、工具说明；不等于全部磁盘历史。
Turn / 轮
在入门 Agent 事件协议中，一次模型回复及其工具执行。
Run / 一次任务运行
用户发起的一次处理，可含多轮，直到停止/取消/失败。
Session / 会话
跨运行的历史与配置组织单位，可带持久化和分支。
Compaction / 上下文压缩
用摘要等方式减少模型可见历史；不是对模型训练，也不等于删除所有原始会话记录。
Skill / 技能
可加载的任务说明和辅助资源；不是自动增加模型权重，也不是 tool.execute 函数的同义词。

六段学习路线

  1. 已生成模型—工具—模型闭环：运行 Python 示例，说明四条消息。
  2. 消息和工具协议：写一个只读工具，测试未知工具、非法参数和错误结果。
  3. 状态和流式事件：把同步循环变成 async；把消息状态与 UI 回调分开。
  4. 组装一个编码助手：解释 createAgentSession 为什么不是“智能本身”，理解默认工具和 system prompt。
  5. 会话与上下文：做 JSONL 存取，区分完整历史、模型上下文和长期记忆。
  6. 可靠运行：研究 AgentHarness 的意图/结果、恢复、幂等与取消；最后再按需求加扩展或多 agent。

后五段是课程范围，不是已完成课件。每段先用 Python 掌握一个可验证行为，再读相应 TS。能在纯 Python 中解释和实现机制后，再决定是否接入真实 provider。
