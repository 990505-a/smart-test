# Wiki 知识库查询 Skill

## 激活场景

- 需求文档引用了业务规则或技术规范时
- 用户提到具体项目名称或系统模块时
- 需要了解已有测试标准和最佳实践时
- 需求分析阶段发现领域专业术语需要解释时
- 测试策略制定需要参考历史测试经验时
- 用户明确要求参考知识库中的已有文档时
- 需要验证功能点是否在历史版本中出现过相关缺陷时

---

## 工具使用指南

本 Skill 通过 wiki-mcp 提供的 6 个工具与知识库交互。所有工具通过 MCP 协议自动暴露给 Agent，无需额外配置。

### 1. list_wikis

**用途**：首先调用，了解可用的知识库项目列表。

**使用时机**：
- 首次查询时，了解当前有哪些知识库可用
- 不确定某个知识领域是否有对应 wiki 时

**参数**：无需参数。

**示例返回**：可用 wiki 名称列表，如 `["test-knowledge"]`。

### 2. search

**用途**：主要查询工具，支持中英文关键词搜索。

**使用时机**：
- 需要查找特定业务规则、技术规范或测试标准
- 需要检索某个领域的知识片段
- 不确定具体页面路径，需要模糊搜索

**参数**：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| query | string | 是 | 搜索关键词，支持中英文 |
| type | string | 否 | 过滤页面类型：entity/concept/source/query/synthesis/comparison |
| maxTokens | number | 否 | 控制返回内容大小，默认由服务端决定 |

**搜索结果特点**：
- 包含 wiki 的 `purpose.md` 上下文
- 返回匹配页面的摘要和路径
- 支持按页面类型过滤

### 3. get_page

**用途**：读取特定页面的完整内容。

**使用时机**：
- 从 `search` 或 `list_pages` 结果中获取到页面路径后
- 需要阅读完整的知识页面内容
- 需要获取某个页面的关联页面

**参数**：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| path | string | 是 | 页面路径（从 search 或 list_pages 结果获取） |
| related | boolean | 否 | 设为 true 可获取关联页面 |

**使用建议**：首次阅读重要页面时建议设置 `related=true`，以发现关联知识。

### 4. list_pages

**用途**：按类型或标签浏览知识库中的所有页面。

**使用时机**：
- 需要浏览某个类型的所有页面（如所有 entity 类型）
- 需要了解知识库的整体结构
- 需要系统性遍历某个领域的所有页面

**参数**：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| type | string | 否 | 页面类型过滤 |
| tag | string | 否 | 标签过滤 |

**页面类型说明**：

| 类型 | 说明 |
|------|------|
| entity | 实体定义（如数据模型、业务对象） |
| concept | 概念解释（如技术术语、业务概念） |
| source | 原始文档（如需求文档、规范文件） |
| query | 常见问题及其解答 |
| synthesis | 综合分析（如跨领域知识整合） |
| comparison | 对比分析（如方案对比、版本差异） |

### 5. graph_query

**用途**：知识图谱查询，发现知识关联关系。

**使用时机**：
- 需要了解实体之间的关联关系
- 需要发现某个知识节点的邻居节点
- 需要追溯知识的引用来源

**参数**：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| mode | string | 是 | 查询模式 |
| node | string | 否 | 目标节点（neighbors 模式必填） |

**查询模式**：

| 模式 | 说明 | 使用场景 |
|------|------|---------|
| neighbors | 发现与指定节点关联的所有页面 | 扩展知识上下文，发现相关业务规则 |
| stats | 获取知识图谱的统计信息 | 了解知识库规模和覆盖范围 |
| trace_source | 追溯指定知识的引用来源 | 验证知识可信度，追溯原始文档 |

### 6. reload

**用途**：当知识库文件有变更时，重建索引。

**使用时机**：
- 知识库目录中新增或修改了文件
- search 结果似乎过时或不完整
- 用户提示知识库内容已更新

**参数**：无需参数。

**注意**：reload 操作可能耗时较长（取决于知识库大小），仅在必要时调用。

## 与工作流的集成

本 Skill 的查询结果**不改变工作流结构**，而是为各阶段提供知识增强，让分析更准确、策略更全面。

### 需求分析阶段（requirement-analysis）

**查询策略**：主动搜索 wiki 获取项目领域知识和业务规则定义。

**具体做法**：
1. 使用 `search` 搜索需求中提到的业务术语和功能模块
2. 使用 `get_page` 获取相关的业务规则详情
3. 将检索到的知识标注 `[Wiki:页面路径]` 纳入功能矩阵
4. 使用 `graph_query(neighbors)` 扩展关联知识

**输出增强**：
- 功能矩阵中补充知识库中的业务规则和约束条件
- 风险清单中标注已知高频缺陷区域
- 术语表与知识库保持一致

### 测试策略阶段（test-strategy）

**查询策略**：查询 wiki 获取测试标准和历史经验。

**具体做法**：
1. 使用 `search` 搜索历史测试策略和测试标准
2. 使用 `list_pages(type="synthesis")` 获取综合性分析文档
3. 参考已有测试策略作为制定依据
4. 使用 `graph_query(stats)` 了解知识库覆盖范围

**输出增强**：
- KUFI 分类参考历史测试经验和缺陷数据
- 测试类型选择参考行业标准知识
- 优先级排序参考历史风险评估

### 用例设计阶段（test-case-design）

**查询策略**：如需补充领域知识，查询相关页面获取细节。

**具体做法**：
1. 对设计中遇到的不确定业务规则，使用 `search` 查找
2. 使用 `get_page(related=true)` 获取页面及其关联内容
3. 将查询结果作为用例设计的补充输入

**其他阶段**（测试数据生成、质量评审、输出格式化）通常不需要查询 wiki 知识库。

## 查询策略建议

### 搜索优先原则

1. **优先使用 `search` 工具**进行关键词检索，这是最高效的查询方式
2. 从 search 结果中选取相关页面，使用 `get_page` 获取详细内容
3. 对重要页面使用 `get_page(related=true)` 获取关联内容
4. 使用 `graph_query(neighbors)` 发现知识关联，扩展上下文

### 查询结果处理规范

- 查询结果应标注来源 `[Wiki:页面路径]`，确保可追溯
- 如果 wiki 知识与用户需求冲突，以用户当前需求为准
- 在分析报告中标注冲突：「知识库冲突：[wiki 规则] vs [当前需求]」
- 建议用户确认冲突内容

### 查询效率建议

- 避免不必要的 `list_pages` 全量调用，优先使用 `search` 精确检索
- 合理使用 `maxTokens` 参数控制返回大小，避免信息过载
- `reload` 仅在确认知识库变更时调用
- 对同一主题的多次查询，复用之前的结果而非重复调用

---

## 输出规范

### 知识引用格式

查询结果应整合到对应阶段的分析输出中，遵循以下规范：

- **引用标注**：所有引用 wiki 内容的地方，标注来源 `[Wiki:页面路径]`
- **整合方式**：将 wiki 知识作为分析依据，融入功能矩阵、风险清单等输出结构中
- **冲突标注**：wiki 知识与需求冲突时，在对应分析项后标注冲突说明

### 未检索到知识的处理

- 在分析中注明「未从知识库获取到相关参考」
- 不影响后续工作流的正常执行
- 建议用户可将相关文档添加到知识库以供后续使用

### 知识增强报告模板

```markdown

### 检索概要
- 查询关键词：[列出使用的搜索关键词]
- 命中页面数：[数量]
- 关联页面数：[通过 graph_query 发现的关联页面数]

### 关键发现
| 知识点 | 来源 | 与当前需求的关系 |
|--------|------|-----------------|
| [业务规则A] | [Wiki:路径] | 直接支撑 [功能点X] 的测试设计 |
| [技术规范B] | [Wiki:路径] | 影响测试策略中的 [测试类型Y] |

### 冲突与差异
| 知识库内容 | 当前需求内容 | 处理方式 |
|-----------|------------|---------|
| [wiki 规则] | [需求描述] | 以当前需求为准，建议确认 |

### 未覆盖领域
- [列出在 wiki 中未检索到的知识领域]
```

## 工具调用决策树

```
开始查询时：
├─ 首次使用？→ list_wikis（了解可用知识库）
├─ 已知关键词？→ search（精确检索）
├─ 已知页面路径？→ get_page（直接读取）
├─ 需要浏览结构？→ list_pages（按类型浏览）
├─ 需要发现关联？→ graph_query(neighbors)
└─ 知识库已更新？→ reload（重建索引）
```
