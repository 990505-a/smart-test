# 测试数据生成 Skill

## 激活场景

- 用户要求为测试用例生成具体的测试数据
- 用例设计阶段需要为每个字段填充具体的输入值
- 需求文档中包含输入字段的定义和约束
- 现有用例缺少具体数据，仅使用占位描述
- 需要对已有数据进行边界值、异常值、安全值的补充

## 核心原则

**铁律：所有测试数据必须是具体值，绝不使用占位描述。**

正确示例：
```
用户名: "admin"
密码: "Admin@123"
金额: 999999.99
手机号: "13800138000"
邮箱: "test@example.com"
```

错误示例（禁止使用）：
```
用户名: [有效用户名]
密码: [正确密码]
金额: [合理金额]
手机号: [合法手机号]
```

> 每个数据值必须是可直接复制粘贴到输入框的具体值，不允许使用括号占位符或描述性文字代替。

## 四类测试数据规范（D-11）

### 一、有效数据（Valid Data）

正常业务值，覆盖最常见的合法输入。

**规则：**
- 每个字段提供 2-3 个典型值
- 覆盖最常见的业务场景
- 包含特殊但合法的值（如含空格的姓名、带小数的金额）

**示例：**

| 字段 | 有效值1 | 有效值2 | 有效值3 | 说明 |
|------|---------|---------|---------|------|
| 用户名 | `"admin"` | `"张三_zhang"` | `"user2024"` | 常见、中文下划线、数字 |
| 密码 | `"Admin@123"` | `"P@ssw0rd!"` | `"Mypwd2024#"` | 含大小写+数字+特殊字符 |
| 手机号 | `"13800138000"` | `"15912345678"` | `"18600001111"` | 不同号段 |
| 邮箱 | `"test@example.com"` | `"user.name@corp.cn"` | `"admin@mail.co.jp"` | 标准格式、含点号、多级域名 |
| 金额 | `99.50` | `0.01` | `999999.99` | 常见、最小、最大 |
| 日期 | `"2024-06-15"` | `"2024-12-31"` | `"2024-01-01"` | 常见、年末、年初 |
| 年龄 | `25` | `18` | `65` | 中间值、最小、最大 |
| URL | `"https://www.example.com"` | `"http://test.cn/path"` | `"https://api.example.com/v1"` | 常见、路径、API |
| 文件名 | `"report.pdf"` | `"data_2024.xlsx"` | `"图片.png"` | 英文、含日期、中文 |

### 二、边界数据（Boundary Data）

针对每个有范围约束的字段，取边界值。Per D-10。

**规则：**
- 对于范围 `[min, max]`，取值：`min-1`, `min`, `min+1`, `中间值`, `max-1`, `max`, `max+1`
- 字符串长度边界：空字符串、1字符、最小长度、最大长度、最大长度+1
- 数值边界：0、负数、最小值、最大值、溢出值
- 日期边界：年起止、月末（28/29/30/31）、闰年2月29日

**示例：**

| 字段约束 | 边界值 | 说明 |
|----------|--------|------|
| 密码长度6-20字符 | `"12345"`（5位）、`"123456"`（6位）、`"1234567"`（7位）、`"abcdefghijklmnopqrst"`（20位）、`"abcdefghijklmnopqrstu"`（21位） | min-1, min, min+1, max, max+1 |
| 金额范围0.01-999999.99 | `0.00`, `0.01`, `0.02`, `500000.00`, `999999.98`, `999999.99`, `1000000.00` | 完整边界序列 |
| 年龄范围18-65岁 | `17`, `18`, `19`, `41`, `64`, `65`, `66` | 完整边界序列 |
| 手机号11位数字 | `"1380013800"`（10位）、`"13800138000"`（11位）、`"138001380000"`（12位） | 长度边界 |
| 文本框最多200字符 | `""`（空）、`"a"`（1字符）、`"a"*200`（200字符）、`"a"*201`（201字符） | 长度边界 |
| 整数范围1-100 | `0`, `1`, `2`, `50`, `99`, `100`, `101` | 数值边界 |

### 三、无效数据（Invalid Data）

格式错误、类型不匹配、空值、超长输入、非法字符等。

**规则：**
- 覆盖每种输入类型的常见无效值
- 包含空值、null、空白字符等边界情况
- 覆盖类型混淆（数字字段传字符串、日期格式错误等）

**示例：**

| 字段类型 | 无效值 | 错误类别 |
|----------|--------|----------|
| 用户名 | `""`（空）、`"  "`（空白）、`"a"`（太短）、`"a"*101`（超长） | 长度/空值 |
| 手机号 | `"abc"`（非数字）、`"123"`（太短）、`"+86-138-0013-8000"`（含特殊字符） | 格式错误 |
| 邮箱 | `"plaintext"`（无@）、`"@domain.com"`（无用户名）、`"user@"`（无域名）、`"user@.com"`（域名无效） | 格式错误 |
| 数值字段 | `"abc"`（非数字）、`None`（空）、`""`（空字符串）、`1.2.3`（多小数点） | 类型不匹配 |
| 日期字段 | `"2024-13-01"`（无效月份）、`"2024-02-30"`（无效日期）、`"not-a-date"`（格式错误） | 格式错误 |
| 文件上传 | `null`（空）、`"hack.exe"`（非法类型）、50MB文件（超大文件）、`""`（空文件名） | 类型/大小 |
| 下拉选项 | `"不存在的选项"`、`999`（越界索引）、`""`（空） | 越界/非法 |

### 四、安全攻击数据（Security Attack Data）

模拟恶意输入，验证系统的安全防护能力。

**规则：**
- 每个文本输入字段至少覆盖 SQL 注入和 XSS 两种攻击
- 标注"仅供测试使用"，严禁在生产环境使用
- 包含路径遍历、命令注入等常见攻击向量

**示例：**

| 攻击类型 | 攻击数据 | 预期防护 |
|----------|----------|----------|
| SQL注入 | `admin' OR '1'='1` | 参数化查询，返回空或错误 |
| SQL注入 | `'; DROP TABLE users; --` | 参数化查询，语句不被执行 |
| SQL注入 | `1 UNION SELECT * FROM passwords --` | 拦截UNION关键字 |
| XSS（存储型） | `<script>alert('XSS')</script>` | HTML实体转义 |
| XSS（反射型） | `"><img src=x onerror=alert(1)>` | 输出编码 |
| XSS（DOM型） | `javascript:alert(document.cookie)` | URL验证拦截 |
| 路径遍历 | `../../../etc/passwd` | 路径规范化+白名单 |
| 路径遍历 | `..\\..\\..\\windows\\system32\\config\\sam` | Windows路径遍历防护 |
| 命令注入 | `; ls -la` | 命令参数化 |
| 命令注入 | `| cat /etc/shadow` | 管道符过滤 |
| LDAP注入 | `*)(|(cn=*))` | LDAP特殊字符转义 |
| XML注入 | `<?xml version="1.0"?><!DOCTYPE foo [<!ENTITY xxe SYSTEM "file:///etc/passwd">]>` | 禁用外部实体 |
| 越权访问 | 修改请求中的 `user_id` 为其他用户ID | 服务端权限校验 |
| CSRF | 伪造跨站请求带合法Cookie | CSRF Token验证 |

## 数据生成工作流

### Step 1：约束分析

对每个输入字段，提取以下信息：
- **数据类型**：字符串/数字/日期/枚举/文件/布尔
- **长度约束**：最小长度、最大长度
- **值域约束**：最小值、最大值、枚举值列表
- **格式约束**：正则表达式、固定格式（如手机号、邮箱）
- **业务约束**：唯一性、关联性、依赖其他字段

### Step 2：按类别生成数据

按四类数据规范（有效/边界/无效/安全），为每个字段生成具体值：

```
字段：密码
约束：长度6-20字符，含大小写字母+数字+特殊字符

有效数据：Admin@123, P@ssw0rd!, Mypwd2024#
边界数据：Admin1!（6位最小）, Aa1!Aa1!Aa1!Aa1!Aa1!（20位最大）, Admin（5位不足）
无效数据：""（空）, 123456（纯数字）, abcdef（纯字母）
安全数据：Admin' OR '1'='1, <script>alert(1)</script>
```

### Step 3：组合到用例

将生成的数据值填充到对应测试用例的"测试数据"字段中。每个用例选择适合其场景的数据类别：

| 用例类型 | 数据类别 | 示例 |
|----------|----------|------|
| 正向功能测试 | 有效数据 | 用户名: `"admin"`, 密码: `"Admin@123"` |
| 边界值测试 | 边界数据 | 密码: `"12345"`（5位，低于最小长度） |
| 异常测试 | 无效数据 | 手机号: `"abc"`, 邮箱: `"plaintext"` |
| 安全测试 | 安全攻击数据 | 用户名: `admin' OR '1'='1` |

### Step 4：标注数据来源

每个数据值标注其类别和生成依据：

```markdown
**测试数据**：
- 用户名: `admin` [有效数据 - 常见管理员账户名]
- 密码: `Admin@123` [有效数据 - 满足6-20位+大小写+数字+特殊字符]
- 金额: `0.00` [边界数据 - 低于最小值0.01]
- 手机号: `<script>alert(1)</script>` [安全数据 - XSS攻击 - 仅供测试使用]
```

## 与其他 Skill 的协作

| 协作 Skill | 协作方式 | 说明 |
|------------|----------|------|
| **test-case-design** | 并行激活 | 用例设计时同步填充具体数据，而非事后补充 |
| **quality-review** | 输入到审查 | 质量审查检查数据是否为具体值（非占位符） |
| **output-formatter** | 数据包含在导出 | 导出时测试数据列包含生成的具体值 |
| **requirement-analysis** | 约束来源 | 从需求分析中提取字段约束作为数据生成依据 |

### 典型协作流程

```
requirement-analysis（提取字段约束）
    -> test-case-design（设计用例框架）
        -> test-data-generator（填充具体数据）
            -> quality-review（检查数据具体性）
                -> output-formatter（导出含数据的用例）
```

## 注意事项

1. **安全数据标注**：所有安全攻击数据必须标注"仅供测试使用"，严禁在生产环境执行
2. **敏感数据脱敏**：涉及身份证号、银行卡号等敏感信息时使用脱敏格式，如 `110***********1234`
3. **数值边界精度**：数值边界数据必须标注单位，如 `金额: 999999.99（元）`、`重量: 0.01（千克）`
4. **枚举全覆盖**：对于下拉选项、单选框等枚举类型字段，每个选项至少生成一条有效数据
5. **关联字段一致性**：关联字段的数据必须保持逻辑一致（如省份-城市、开始日期-结束日期）
6. **国际化数据**：如需求涉及多语言，需包含中文、英文、日文、特殊Unicode字符等测试数据
7. **时区感知**：日期时间数据应标注时区，如 `2024-06-15T10:30:00+08:00（北京时间）`
8. **数据量标注**：大数据量场景需标注具体数量，如 `导入10000条用户记录`、`查询结果含500+条`
