# 问剑长生 · Unity 自动化工程

这个目录是**一个被测游戏**的自动化用例工程（不是某一条用例）。每一次跑、改、查，
入口都在这里；游戏侧的知识也沉淀在这里，不写在平台里。

## 目录形状

| 目录 | 放什么 | 能改吗 |
|---|---|---|
| `lib/` | **机制与游戏知识**：`00_head.py`（import + 起跑线 + 本游戏对象路径常量）、`10_ui.py`（wait_visible / tap / expect_text 等基础操作）、`20_map.py`（地图格、探雾、世界坐标→屏幕坐标、拖拽，含内嵌 C#/Lua）、`30_flow.py`（找子节点、推进剧情、连点、console 检查） | ✅ 要改就改这里 |
| `cases/<用例>/` | **某一用例的正文与工件**：`stage*_body.py`（正文）、`raw/`（录制原稿与归一化器）、`build.py`（构建器）、`dist/`（生成物）、`case.md`（门面） | ✅ 正文可改；`dist/` 不可改 |
| `docs/` | **按需读的专题知识**（探雾原理、截图边界、历史坑位）。不进常驻记忆，用到时读 | ✅ |
| `tools/` | 仍在用的只读探针（如 `probe_cell_xy.py`：证明 guide 标记被摆高了 110px） | ✅ |
| `archive/` | 一次性脚本与迁移前快照，**按日期归档、永不删、不要读** | ❌ 只读 |

> `lib/*.py` 是**同一模块的四个片段**：`build.py` 按文件名顺序拼接它们，
> 拼接结果就是原来的单文件 `flow_header.py`。所以不要单独 import 某个片段。

## 三条命令

```bash
# 跑：用平台里注册的那条用例（页面「执行」按钮，或智能体的 unity_run_script(script_id=…)）
#    不要直接跑 dist/ 里的文件，那会绕过平台的存证、录像、失败现场

# 改：改 lib/ 或 cases/<用例>/ 的源码 → 重新构建 → 重跑 → 跑通后回存平台
cd workspace/default/automation/unity/问剑长生/cases/新手流程 && python build.py

# 看：先看 cases/<用例>/case.md（起跑线 / 目标 / 跑到哪了 / 上次为什么挂）
```

## 硬规则

1. **`dist/` 永不手改**。它是生成物，改了会被下次构建覆盖；构建是可复现的。
2. **`archive/` 不读**。历史现场，与本轮无关。
3. **跑不通先看 `failure.kind`**：`case` 才改用例（按 `failure.artifacts` 的
   `failure.txt` / `steps.jsonl` / `failure.png` 定位）；`environment` 停下报环境问题，
   **改用例是白改**。
4. **不许为了变绿放宽或删断言**。
