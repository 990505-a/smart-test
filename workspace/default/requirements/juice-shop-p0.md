# Juice Shop 电商平台 — 需求规格说明书（P0）

> 版本：v1.0　范围：P0（账号、商品浏览与搜索、购物车、结算下单）
> 被测系统：OWASP Juice Shop v20.2.0（测试环境 http://juice-shop:3000）
> 说明：本文件是**需求的唯一事实源**，用例应逐条追溯到下方的 REQ 编号。

---

## 1. 背景与目标

Juice Shop 是一个在线果汁电商站点。用户可浏览商品、搜索、加入购物车、结算下单并查看订单。
本次测试范围覆盖**顾客侧主流程**（注册 → 登录 → 找商品 → 加购物车 → 结算 → 查订单），
目标是验证主流程可用、校验规则正确、金额计算准确、异常输入有合理反馈。

## 2. 术语

| 术语 | 含义 |
|---|---|
| 商品（Product） | 可售卖的果汁/周边，含名称、描述、单价、图片 |
| 购物车（Basket） | 当前用户的待结算商品集合 |
| 结算（Checkout） | 选择地址 → 选择配送方式 → 选择支付方式 → 提交订单 |
| 订单（Order） | 结算成功后生成的记录，含商品明细与总金额 |

## 3. 功能需求

### 3.1 账号与登录

**REQ-AUTH-001　用户注册**
- 描述：访客可用邮箱注册新账号。注册表单包含：邮箱、密码、确认密码、安全问题（下拉选择）、安全问题答案。
- 规则：
  - 邮箱必填且需符合邮箱格式；邮箱不可与已有账号重复。
  - 密码必填；输入时实时显示密码强度。
  - 确认密码必须与密码一致，不一致时不得提交。
  - 安全问题需从系统提供的列表中选取（系统提供 14 个问题）。
- 验收：注册成功后，使用该邮箱与密码可成功登录。

**REQ-AUTH-002　用户登录**
- 描述：已注册用户可用邮箱 + 密码登录。
- 规则：
  - 正确凭据登录成功，进入已登录状态（页面显示用户菜单）。
  - 错误凭据登录失败，给出明确错误提示，且停留在登录页。
  - 邮箱不存在与密码错误，提示信息不区分（出于安全考虑）。
- 验收：错误密码时页面出现错误提示且未进入登录态。

**REQ-AUTH-003　退出登录**
- 描述：已登录用户可退出登录，退出后回到未登录状态，受保护页面不可访问。

### 3.2 商品浏览与搜索

**REQ-CAT-001　商品列表**
- 描述：首页与商品页以卡片网格展示商品，卡片包含商品图片、名称、价格。
- 规则：默认展示全部商品（系统共 46 个商品）；卡片可点击进入详情。

**REQ-CAT-002　商品搜索**
- 描述：页面顶部提供搜索框，输入关键字后展示匹配商品。
- 规则：
  - 采用**子串模糊匹配**（例如搜 `apple` 会同时命中 `Apple Juice` 与 `Pineapple Juice`）。
  - 匹配不区分大小写。
  - 关键字无匹配时，结果区为空且不报错。
  - 清空关键字后恢复展示全部商品。
- 验收：搜索 `apple` 的结果中包含名称含 `apple`/`Apple`/`Pineapple` 的商品。

**REQ-CAT-003　商品详情**
- 描述：点击商品卡片进入详情页，展示名称、描述、价格、图片、用户评价。
- 规则：详情页提供「加入购物车」按钮；未登录时也可加入购物车。

**REQ-CAT-004　界面语言切换**
- 描述：页面提供语言选择入口，可切换界面语言。
- 规则：系统支持包括简体中文在内的多语言（43 种）；切换后界面文案随之变化，且刷新后保持。

### 3.3 购物车

**REQ-CART-001　加入购物车**
- 描述：在商品详情页点击「加入购物车」，商品进入购物车。
- 规则：
  - 加入后给出成功反馈（提示条）。
  - 购物车角标数量随之增加。
  - 同一商品重复加入时，数量累加而非新增一行。

**REQ-CART-002　购物车数量调整**
- 描述：购物车中可增加/减少单个商品数量。
- 规则：
  - 数量增加时，该行小计与购物车总金额同步更新。
  - 数量减少到 1 时，继续减少应移除该商品（或最小为 1，以产品实际行为为准，需在用例中固化）。
  - 总金额恒等于各商品「单价 × 数量」之和。

**REQ-CART-003　移除商品**
- 描述：可删除购物车中的单个商品。
- 规则：删除后该商品不再出现在购物车，总金额相应减少；删除唯一商品后购物车为空。

**REQ-CART-004　空购物车**
- 描述：购物车为空时，展示空状态提示，且不提供结算入口。

### 3.4 结算与订单

**REQ-ORDER-001　进入结算**
- 描述：购物车非空时可点击「结账」进入结算流程。
- 规则：未登录用户点击结账时，应先要求登录（或跳转登录页）；登录后回到结算流程。

**REQ-ORDER-002　选择收货地址**
- 描述：结算第一步选择收货地址，可从已保存地址中选择，或新增地址。
- 规则：
  - 新增地址表单包含：国家/地区、姓名、手机号、邮编、地址、城市。
  - 必填项缺失时不得提交，并给出字段级提示。
- 验收：缺少必填项的地址无法提交。

**REQ-ORDER-003　选择配送方式**
- 描述：结算第二步选择配送方式，系统提供「标准配送」等选项。
- 规则：不同配送方式影响最终总金额（配送费），选择后金额实时更新。

**REQ-ORDER-004　选择支付方式**
- 描述：结算第三步选择支付方式，系统提供多种支付方式（如钱包、信用卡等）。
- 规则：需选择一种支付方式才能提交订单；选择后展示对应支付信息项。

**REQ-ORDER-005　提交订单**
- 描述：确认订单后提交，系统生成订单并展示订单确认信息。
- 规则：
  - 提交成功后：购物车被清空，生成一条订单记录，页面给出成功反馈。
  - 订单总额 = 商品小计 + 配送费。
  - 提交后订单出现在「订单历史」中。

**REQ-ORDER-006　订单历史**
- 描述：已登录用户可查看自己的历史订单列表。
- 规则：列表按时间倒序；未登录用户不可访问该页面；用户只能看到自己的订单。

## 4. 非功能需求

**REQ-NFR-001　浏览器兼容**：页面在 Chromium 内核浏览器下可正常渲染与操作。
**REQ-NFR-002　响应式**：页面在移动端视口（如 iPhone 13 尺寸）下布局可用，无横向溢出。
**REQ-NFR-003　数据隔离**：不同用户之间的购物车、地址、订单互不可见。

## 5. 明确的边界与异常（用例必须覆盖）

| 编号 | 场景 | 期望 |
|---|---|---|
| EDGE-001 | 注册时两次密码不一致 | 阻止提交并提示 |
| EDGE-002 | 注册使用已存在的邮箱 | 阻止提交并提示邮箱已被占用 |
| EDGE-003 | 登录时密码错误 | 停留在登录页并提示错误 |
| EDGE-004 | 搜索不存在的关键字（如 `zzzz`） | 结果为空，页面不报错 |
| EDGE-005 | 搜索特殊字符（如 `%`、`<script>`） | 页面不崩溃、不出现脚本执行 |
| EDGE-006 | 购物车数量减到 0 | 商品被移除或数量保持 1（需固化实际行为） |
| EDGE-007 | 新增地址时留空必填字段 | 无法提交并给出提示 |
| EDGE-008 | 购物车为空时访问结算 | 无法进入结算流程 |
