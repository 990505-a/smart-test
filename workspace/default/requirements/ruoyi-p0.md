# 芋道管理系统（ruoyi-vue-pro）— 需求规格说明书（P0）

> 版本：v1.0　范围：P0（系统管理 + 基础设施）
> 被测系统：ruoyi-vue-pro（芋道）单体版 — Spring Boot 后端 + MySQL 8 + Redis 6 + Vue3 管理后台
> 测试环境：http://yudao-admin （容器内直连，本文件所用路由与字段均以此为准）
> 说明：本文件是**需求的唯一事实源**，用例应逐条追溯到下方的 REQ 编号。
> 文中列名 / 按钮文案 / 查询条件均取自被测环境实际页面，不是产品文档的转述。

---

## 1. 背景与目标

芋道管理系统是一套通用后台管理平台，核心能力是**租户 + RBAC + 数据权限**三层访问控制，
以及围绕它展开的用户/角色/菜单/部门/岗位/字典等系统管理与代码生成、文件、定时任务等基础设施能力。

本次测试范围锁定在**平台自身的系统管理与基础设施**（即登录后「系统管理」「基础设施」两个一级菜单），
目标是验证：登录与租户隔离正确、权限控制生效、各管理页面增删改查可用、校验规则与异常反馈合理。

**不测**未启用的业务模块（CRM / ERP / Mall / 支付等）——这些模块的菜单已清理，界面上不出现；
种子数据里残留的相关字典与定时任务只作为数据存在，不验证其业务含义。

## 2. 术语

| 术语 | 含义 |
|---|---|
| 租户（Tenant） | 数据隔离单位。同一套部署服务多个租户，租户之间数据互不可见 |
| 菜单权限 | 控制菜单项与页面内按钮是否对某角色可见、可点 |
| 数据权限 | 同一租户内，按「全部 / 自定义部门 / 本部门 / 本部门及以下 / 仅本人」等范围过滤数据 |
| 内置数据 | 系统初始化写入的角色/菜单/用户，界面上标记为「内置」，不允许删除 |
| 逻辑删除 | 删除只置 `deleted` 标记，数据库中保留记录，列表不再展示 |
| 权限标识 | 形如 `system:user:create` 的字符串，后端按它校验接口权限 |

## 3. 功能需求

### 3.1 登录与身份

**REQ-AUTH-001　租户登录**
- 描述：登录页 `/login` 提供「登录 / 手机登录 / 二维码登录」三种方式，默认方式（登录）的表单包含
  **租户名称、用户名、密码** 三个输入项（占位分别为「请输入租户名称」「请输入用户名」「请输入密码」），
  以及「记住我」复选框。
- 规则：
  - 三项均为必填；任一项留空时不得提交。
  - 凭据正确 → 进入系统首页 `/index`，顶栏显示当前租户名与当前用户昵称。
  - 凭据错误 → **停留登录页**并给出错误提示，不进入系统。
  - 租户名称不存在时登录失败（租户名决定数据范围，不能忽略）。
- 验收：使用正确租户名 + 正确用户名密码可登录并到达 `/index`；密码错误时仍停在 `/login`。

**REQ-AUTH-002　记住我**
- 描述：登录表单提供「记住我」复选框（默认勾选）。
- 规则：勾选后登录，在**同一浏览器**重新打开页面仍保持登录态；不勾选时登录态仅在当前会话有效。

**REQ-AUTH-003　退出登录**
- 描述：顶栏用户菜单提供「退出登录」。
- 规则：退出后回到登录页；退出后直接访问受保护路由（如 `/system/user`）应被重定向回登录页，
  不得渲染页面内容。

**REQ-AUTH-004　登录后导航与租户视图**
- 描述：登录成功后进入首页 `/index`；左侧侧边栏一级菜单包含「首页」「系统管理」「基础设施」
  以及两个外链（Boot 开发文档、Cloud 开发文档）；顶栏提供租户选择框（占位文案「请选择租户」）
  与菜单搜索框（占位文案「请输入菜单内容」）。
- 规则：
  - 侧边栏只渲染**当前账号有权限**的菜单项。
  - 菜单搜索框输入关键字后，侧边栏按关键字过滤菜单。
  - 首页展示欢迎信息、统计卡片与快捷入口，属于静态展示，不参与数据校验。

**REQ-AUTH-005　修改个人密码**
- 描述：个人中心提供修改密码，需填写旧密码与新密码。
- 规则：新密码长度限 4–16 位；旧密码错误时不得修改成功；修改成功后可用新密码登录。

**REQ-AUTH-006　自助注册与默认权限**
- 描述：登录页提供「注册」入口，是否开放由参数 `system.user.register-enabled` 控制（本环境为开启）。
- 规则：自助注册产生的账号**默认不带任何角色**；此类账号登录后仅能看到首页，
  管理菜单不可见，直至管理员为其分配角色。

### 3.2 用户管理（`/system/user`）

**REQ-USER-001　用户列表**
- 描述：以分页表格展示用户，列包含：用户编号、用户名称、用户昵称、部门、手机号码、状态、创建时间、操作。
- 规则：左侧提供**部门树**，点击某部门后列表只展示该部门（含子部门）的用户；
  列表底部显示总数与分页控件。行内操作提供「修改」与「更多」。

**REQ-USER-002　用户查询**
- 描述：查询区包含「用户名称（请输入用户名称）、手机号码（请输入手机号码）、状态（请选择用户状态）、
  创建时间（开始日期—结束日期）」四个条件。
- 规则：
  - 多个条件为**与**关系。
  - 「重置」清空所有条件并恢复全量列表。
  - 查询无匹配时表格为空且页面不报错。

**REQ-USER-003　新增用户**
- 描述：「新增」按钮打开弹窗，填写用户信息并选择所属部门与角色。
- 规则：
  - 用户名称、用户昵称、所属部门为必填；缺失时不得提交并给出提示。
  - 用户名称在**租户内唯一**，重复时阻止提交并提示。
  - 新增成功后，列表能查到该用户。

**REQ-USER-004　修改用户**
- 描述：行内「修改」打开编辑弹窗并回显当前值；保存后列表显示修改后的值。

**REQ-USER-005　删除用户**
- 描述：支持单行删除与勾选多行后的「批量删除」。
- 规则：
  - 内置管理员账号（admin）不允许删除。
  - 不允许删除当前登录账号自身。
  - 删除为逻辑删除：列表不再显示，数据库中记录保留。

**REQ-USER-006　重置密码**
- 描述：行内「更多」提供「重置密码」，为指定用户设置新密码。
- 规则：重置后可用新密码登录（需满足密码长度规则）。

**REQ-USER-007　用户状态启停**
- 描述：列表「状态」列可切换启用/停用。
- 规则：停用后的账号**不能登录**；重新启用后可正常登录。

**REQ-USER-008　导入与导出**
- 描述：工具条提供「导入」「导出」按钮。导出将当前查询条件下的用户数据下载为 Excel。
- 规则：导出文件可正常下载且非空；导入要求模板格式正确，格式错误时给出提示且不产生脏数据。

**REQ-USER-009　分配角色**
- 描述：新增/修改用户时可为其勾选一个或多个角色。
- 规则：角色决定该用户登录后可见的菜单与可执行的操作；取消角色后对应菜单不再可见。

### 3.3 角色管理（`/system/role`）

**REQ-ROLE-001　角色列表**
- 描述：分页表格列包含：角色编号、角色名称、角色类型（内置/自定义）、角色标识、显示顺序、备注、状态、创建时间、操作。
- 规则：行内操作提供「编辑」「菜单权限」「数据权限」「删除」。

**REQ-ROLE-002　角色查询**
- 描述：查询条件包含「角色名称（请输入角色名称）、角色标识（请输入角色标识）、状态、创建时间（起止）」；
  「重置」清空条件。

**REQ-ROLE-003　新增与修改角色**
- 描述：「新增」/「编辑」打开弹窗，填写角色名称、角色标识、显示顺序、状态、备注。
- 规则：
  - 角色名称、角色标识为必填。
  - 角色标识**租户内唯一**，重复时阻止提交并提示。
  - 保存成功后列表出现/更新该角色。

**REQ-ROLE-004　删除角色**
- 描述：支持单行删除与批量删除。
- 规则：
  - **内置角色不允许删除**（超级管理员、普通角色、CRM 管理员标记为「内置」）。
  - 角色已被用户引用时，删除应被拒绝或给出明确影响提示。

**REQ-ROLE-005　菜单权限分配**
- 描述：行内「菜单权限」打开权限树弹窗，可为该角色勾选可见的目录 / 菜单 / 按钮。
- 规则：
  - 树为三级结构：目录 → 页面 → 按钮。
  - 勾选父节点时子节点可整体选中（父子联动）。
  - 保存后，使用该角色的用户重新登录，侧边栏与页面按钮随之变化
    （**未勾选的菜单不出现，未勾选的按钮不显示**）。

**REQ-ROLE-006　数据权限分配**
- 描述：行内「数据权限」打开弹窗，为该角色设置**数据范围**，并可进一步指定自定义部门。
- 规则：
  - 数据范围至少包含：全部数据、指定部门、本部门、本部门及以下、仅本人。
  - 选择「指定部门」时可勾选具体部门，保存后该角色用户只能看到范围内部门的数据。

### 3.4 菜单管理（`/system/menu`）

**REQ-MENU-001　菜单树列表**
- 描述：以可展开/折叠的树形表格展示菜单；查询条件为「菜单名称（请输入菜单名称）、状态」；
  工具条提供「搜索 / 重置 / 新增 / 展开折叠 / 刷新菜单缓存」。
- 规则：行内操作提供「修改」「删除」。

**REQ-MENU-002　新增与修改菜单**
- 描述：可新增菜单，**类型可为「目录 / 菜单 / 按钮」三种**，上级菜单从树中选取。
- 规则：
  - 目录与菜单需填写路由地址；菜单需填写组件路径；按钮需填写权限标识。
  - 菜单名称在同一父节点下不应重复。
  - 保存成功后菜单树出现该节点。

**REQ-MENU-003　删除菜单**
- 描述：支持删除单个菜单节点。
- 规则：**存在子菜单的节点不允许删除**（或需先删除子节点），应给出明确提示。

**REQ-MENU-004　刷新菜单缓存**
- 描述：工具条提供「刷新菜单缓存」按钮。
- 规则：点击后菜单缓存的版本被刷新（后端返回成功），不影响当前已渲染的菜单结构。

### 3.5 部门与岗位

**REQ-DEPT-001　部门树（`/system/dept`）**
- 描述：以树形表格展示部门层级，列含部门名称、负责人、排序、状态、创建时间、操作；
  查询条件为「部门名称（请输入部门名称）、部门状态」；工具条提供「搜索 / 重置 / 新增 / 展开折叠 / 批量删除」。
- 规则：部门层级深度不固定（如「深圳总公司 → 研发部门」「长沙分公司 → 市场部门」）。

**REQ-DEPT-002　新增与修改部门**
- 描述：可新增下级部门或修改现有部门，填写上级部门、部门名称、显示排序、负责人、状态。
- 规则：部门名称在同一父部门下不应重复；保存成功后树中出现该节点。

**REQ-DEPT-003　删除部门**
- 规则：**存在子部门或存在关联用户的部门不允许删除**，应给出明确提示。

**REQ-POST-001　岗位管理（`/system/post`）**
- 描述：分页表格列含岗位编号、岗位名称、岗位编码、岗位顺序、岗位备注、状态、创建时间、操作；
  查询条件为「岗位名称（请输入岗位名称）、岗位编码（请输入岗位编码）、状态」；
  工具条提供「搜索 / 重置 / 新增 / 导出 / 批量删除」；行内操作提供「编辑」「删除」。

**REQ-POST-002　岗位导出**
- 描述：提供「导出」按钮，将岗位数据下载为 Excel。

### 3.6 字典管理（`/system/dict`）

**REQ-DICT-001　字典类型列表与查询**
- 描述：以「字典类型 → 字典数据」两级结构管理。字典类型表列含字典编号、字典名称、字典类型、状态、
  备注、创建时间、操作；查询条件为「字典名称（请输入字典名称）、字典类型（请输入字典类型）、状态、创建时间」；
  工具条提供「搜索 / 重置 / 新增 / 导出 / 批量删除」；行内操作提供「修改」「数据」「删除」。
- 规则：列表分页并显示总数（本环境 292 条）。

**REQ-DICT-002　新增与修改字典类型**
- 规则：字典名称与字典类型为必填；**字典类型标识唯一**，重复时阻止提交并提示。

**REQ-DICT-003　字典数据管理**
- 描述：行内「数据」进入该字典类型的字典数据维护页（字典标签、字典键值、排序、状态、颜色类型等）。
- 规则：新增数据项保存后列表出现该项；修改后列表显示新值。
- **待执行时确认**：字典数据页的具体列名与按钮未在做需求时逐一核实，用例以「点击行内『数据』能进入、
  能新增一条数据项并在列表中查到」为断言粒度，不要写死未核实的字段名。

**REQ-DICT-004　删除字典**
- 描述：支持删除字典类型与单个字典数据项。
- 规则：内置字典类型删除应被拒绝或给出明确提示；删除后列表不再显示。

### 3.7 租户管理（`/system/tenant/list`）

**REQ-TENANT-001　租户列表**
- 描述：分页表格列含租户编号、租户名、租户套餐、联系人、联系手机、账号额度、过期时间、绑定域名、
  租户状态、创建时间、操作；查询条件为「租户名、联系人、联系手机、租户状态、创建时间」；
  工具条提供「搜索 / 重置 / 新增 / 导出 / 批量删除」；行内操作提供「编辑」「删除」。
- 规则：本环境共 3 条租户。

**REQ-TENANT-002　租户套餐**
- 描述：维护租户套餐（套餐名称、状态、备注），用于约束某租户可使用的菜单范围。
- **待执行时确认**：该页面的列名与按钮未在做需求时核实。可用断言粒度：新增一条套餐后列表能查到。
  **不要**断言「套餐配置的菜单范围与实际可见菜单一致」——套餐如何限定菜单范围未经验证。

**REQ-TENANT-003　租户数据隔离**
- 描述：不同租户之间的用户、角色、部门、字典等业务数据相互隔离。
- 规则：以租户 A 的身份登录，**看不到**租户 B 的用户与角色；同一账号名可在不同租户下独立存在。

### 3.8 日志与公告

**REQ-LOG-001　操作日志（`/system/log/operate-log`）**
- 描述：记录后台的写操作。列表列含日志编号、操作人、操作模块、操作名、操作内容、操作时间、
  业务编号、操作 IP、操作（详情）；查询条件为「操作人、操作模块、操作名、操作内容、操作时间、业务编号」；
  工具条提供「搜索 / 重置 / 导出」。
- 规则：执行一次新增/修改/删除操作后，能在操作日志中查到对应记录（操作人、模块、操作名与实际动作一致）。

**REQ-LOG-002　登录日志（`/system/log/login-log`）**
- 描述：列表列含日志编号、登录类型、用户名称、登录地址、浏览器、登陆结果、登录日期、操作；
  查询条件为「用户名称、登录地址、登录日期」；工具条提供「搜索 / 重置 / 导出」；行内提供「详情」。
- 规则：一次成功登录与一次失败登录都应产生记录，并在「登陆结果」上体现差异。

**REQ-NOTICE-001　通知公告（`/system/messages/notice`）**
- 描述：列表列含公告编号、公告标题、公告类型、状态、创建时间、操作；查询条件为「公告标题、公告状态」；
  工具条提供「搜索 / 重置 / 新增 / 批量删除」；行内操作提供「编辑」「删除」「推送」。
- 规则：新增公告保存后列表出现该条；已发布公告出现在首页公告区。

### 3.9 基础设施

**REQ-JOB-001　定时任务列表与查询（`/infra/job`）**
- 描述：分页表格列含任务编号、任务名称、任务状态、处理器的名字、处理器的参数、CRON 表达式、操作；
  查询条件为「任务名称（请输入任务名称）、任务状态、处理器的名字（请输入处理器的名字）」；
  工具条提供「搜索 / 重置 / 新增 / 批量删除 / 导出 / 执行日志 / 同步任务」；行内提供「修改」「暂停/开启」「删除」「更多」。

**REQ-JOB-002　任务状态启停**
- 描述：行内可对任务执行「暂停」或「开启」。
- 规则：切换后任务状态列随之变化；**暂停状态下任务不再被调度**。

**REQ-JOB-003　手动执行一次**
- 描述：行内「更多」提供「执行一次」（手动触发）。
- 规则：触发后产生一条执行记录；任务处理逻辑本身是否成功不影响「触发成功」这一事实。

**REQ-JOB-004　任务执行日志**
- 描述：提供「执行日志」入口，展示任务的历史执行记录（执行时间、耗时、执行结果、异常信息）。

**REQ-CONF-001　参数配置（`/infra/config`）**
- 描述：分页表格列含参数主键、参数分类、参数名称、参数键名、参数键值、是否可见、系统内置、备注、
  创建时间、操作；查询条件为「参数名称、参数键名、系统内置、创建时间」；
  工具条提供「搜索 / 重置 / 新增 / 批量删除 / 导出」；行内提供「编辑」「删除」。
- 规则：
  - **参数键名唯一**，重复时阻止提交并提示。
  - 标记为「系统内置」的参数不允许删除。

**REQ-FILE-001　文件管理（`/infra/file/file`）**
- 描述：列表列含文件名、文件路径、URL、文件大小、文件类型、文件内容、上传时间、操作；
  查询条件为「文件路径、文件类型、创建时间」；工具条提供「搜索 / 重置 / 上传文件 / 批量删除」。
- 规则：上传成功后列表出现该文件；删除后列表不再显示。

**REQ-DS-001　数据源配置（`/infra/data-source-config`）**
- 描述：列表列含主键编号、数据源名称、数据源连接、用户名、创建时间、操作；
  工具条提供「新增 / 批量删除」，行内提供「编辑」「删除」。
- 规则：新增数据源后列表出现该条；删除后列表不再显示。
- **边界说明（已核实）**：本版本**没有「测试连接」功能**——该页面无任何查询条件，
  后端也仅有 `create / update / delete / delete-list / get / list` 六个接口，
  不存在连接校验端点。因此**不测**连接可用性校验。

**REQ-CODEGEN-001　代码生成（`/infra/codegen`）**
- 描述：列表列含数据源、表名称、表描述、实体、创建时间、更新时间、操作；查询条件为「表名称、表描述、创建时间」；
  工具条提供「搜索 / 重置 / 导入 / 批量删除」。本环境该列表为空（未导入过任何表）。
- 规则：点击「导入」能打开数据表选择弹窗；选中并导入后列表中能查到该表。
- **待执行时确认**：「编辑生成配置 / 预览 / 下载」这几步的入口与字段未在做需求时核实（列表为空，
  行内操作无从观察）。用例把断言收敛到「导入后列表出现该表」，后续步骤以弹窗内可见的按钮文案为准，
  不要预先假定按钮名称或字段清单。

## 4. 非功能需求

**REQ-NFR-001　浏览器兼容**：页面在 Chromium 内核浏览器下可正常渲染与操作，无控制台致命错误导致白屏。

**REQ-NFR-002　访问控制（未登录）**：未登录状态直接访问任意受保护路由，
应被重定向到登录页，不得渲染页面内容。

**REQ-NFR-003　访问控制（越权）**：不具备某菜单权限的账号，
侧边栏不出现该菜单；直接输入 URL 访问该页面应被拒绝（跳转无权限页或提示），
不得仅靠前端隐藏而让后端接口可任意调用。

**REQ-NFR-004　分页一致性**：所有列表页分页控件的总数、页大小与表格实际行数一致；
切换页码后数据随之变化。

## 7. 环境与假设

1. **环境地址**：容器内直连 `http://yudao-admin`（前端 nginx，`/admin-api` 反代到后端）。
2. **登录凭据**：租户「芋道源码」+ 用户名 `admin` + 部署时设定的管理员密码。
   该账号拥有超级管理员角色，可见全部菜单。
3. **验证码**：本环境已关闭登录图形验证码，登录表单不含验证码输入框。
   因此**不覆盖**验证码相关需求。
4. **数据基线**（测试环境实际观测值，用于数量类断言的参考）：
   - 租户 3 条；租户 1（芋道源码）下用户 15 个、角色 5 个、部门 14 个、岗位 4 个
   - 字典类型 292 条；参数配置 7 条；定时任务 27 条；通知公告 2 条
   - 操作日志 0 条、文件 0 条、代码生成 0 条（初始为空，需由用例自身产生数据）
   - 登录日志 29 条（已有历史数据，随每次登录递增）
   - 角色包含内置角色（超级管理员 `super_admin`、普通角色 `common`、CRM 管理员 `crm_admin`）
     与自定义角色（`test-dp`、`hrm_team_leader`）
5. **种子数据说明**：定时任务与大量字典类型来自官方种子 SQL（含支付、Mall 等未启用模块）。
   本范围内只验证**任务/字典管理功能本身**，不验证这些条目的业务含义；
   因此数量类断言应写成「不少于 N 条」或按名称精确定位，不要写死总数。
6. **写入类用例的前置与清理**：新增/删除类用例需使用可识别的测试数据命名前缀（如 `zz_test_`），
   并在用例结束处清理，避免污染基线数据影响后续回归。
